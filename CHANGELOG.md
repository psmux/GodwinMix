# Changelog

## Unreleased

* A rendition planner, the new crate `godwinmix-render`. Given what every output asks for (container, codec, size, frame rate, bitrate, keyframe interval, audio) and what every source carries, `plan` returns the smallest graph that serves them all: a copy when the source already matches, one decode per source, one scale per distinct size and rate, one encoder per distinct shape shared by every output that wants it, and one keyframe interval across every rendition of a source so a ladder switches cleanly. Encoders are chosen hardware first, never on a device the cost model says is full, and each Encode node says why in a sentence ("using h264-software-x264 because the GPU nvidia0 is full"). A request nothing here can make is refused with the nearest shape that works. `diff` compares two plans so a running show starts, stops or restarts only what changed: adding a rung starts its scale, encoder and mux and nothing else. It is pure Rust with no GStreamer, and 16 sources with 64 outputs plan in about 130 microseconds on an M4 Pro. Nothing uses it yet; wiring it into the core's outputs comes next. See `docs/reference/renditions.md` and `docs/explanation/rendition-planner.md`.
* A resource governor, `crates/godwinmix-govern`, not wired into the mixer yet. It answers one question before anything starts: can this machine do this without taking a frame from what is on air? `Governor::admit(cost, what)` grants a ticket that holds a share of CPU, hardware encoder load and sessions, memory and uplink until it is dropped, or refuses with what the work needs, what is free and which renditions would fit (`1080p30 H.264 on h264-software-x264 fits, or 1080p60 H.264 on the GPU encoder h264-gpu`). What is free is worked out, not set: live load sampled once a second (`/proc` on Linux, Mach host statistics on macOS, `GetSystemTimes` on Windows), other programs counted at their recent peak, and a reserve sized for a desktop or a headless server, with an optional `reserve_cores` override. `shed()` says what to give up when the machine runs short on air: thumbnails and previews, then the lowest ladder rung upward, then faster software presets, never the programme or a live output's top rung. Calibration, behind the `calibrate` feature, times a second of 720p30 and 1080p30 through every catalogue encoder installed, a few x264 presets, a scale, a decode and the audio encoders, and probes hardware session limits; the result is stored per machine by fingerprint and measured again when the hardware, the encoders or GStreamer change, never while on air unless asked. On an M4 Pro the whole calibration took 5.0 s. A load sample costs about 2 µs and an admission about 140 ns. See `docs/reference/governor.md` and `docs/explanation/resource-governor.md`.

* A channel key can be seen and copied again at any time. New method `channel.key.reveal {id, key}`, admin scope, `POST /api/v1/channels/{id}/key/reveal`, reads one key back from the secret store and answers `{secret}`; each call is logged with the key id and the token that asked, never the key. Lists and events still carry only the hint, so a read token never sees a key, and keys made before this release are read back too. On the Channels page every card has **Connect**, folded until opened, listing each key by label with Server, Stream key and Full URL, each with Copy, the key hidden until Show. A stream name box (`main` to start) and the address buttons apply to all three fields and the QR code, so `main_720p` or `cam2` can be copied as easily. Each live stream has a Copy URL for the URL it came in on. The card after create adds the Full URL, and no longer says the key is shown once, which was never true: the mixer always kept it sealed.
* Studio mode can be driven now. A big Take button sits between Preview and Programme, with Cut under it and the transition (Fade or Move) and its length under that. Space takes, and so does a double click on the Preview picture. Preview has a green frame and Programme a red one. A click on a source tile puts that source in Preview; it used to do nothing, because the Sources panel is scoped to a scene and a click there only selected the tile. A click on a scene tab puts that scene in Preview. The Take beside the scene tabs, which armed in Studio mode, is hidden there. A scene whose sources are not all running says so in Preview before Take is pressed, since the core refuses it. After a take Preview keeps what was sent, as the core does with an armed scene. The Studio code loads the first time Studio mode is switched on.
* `program.take {source: ""}` is the slate even while a scene is armed. Cut to black, `0` in the page and `0` in the terminal UI send it; they sent `{}` or `{source: null}`, which took the armed scene, so in Studio mode Cut to black put Preview on air.
* A page opened after a scene was armed shows it in Preview and in the scene tab's tally, read from `scene.list`, and the list's armed flag follows `event/preview.changed`, so a disarmed scene no longer looks armed.

* RTMP channels are one feature now: a channel's destinations run. The ingest plugin starts one restream per destination that is switched on, reading the channel's stream from the hub. A destination waits while its stream is not live, and one set to send whichever stream is live moves to the next when that one leaves. Each reports its state, bit rate, reconnects and error back to the core, which shows them in `channel.list` and sends `event/channel.changed` whenever a destination is added, changed or removed, or its state moves. Destinations are kept with their channel in `<stem>.runtime.channels.toml`, their addresses and keys sealed in the secret store beside the channel's keys, and come back after a restart. On one channel with two live 720p streams and three destinations, the channel server process measured about 1.2% of one core and 13 MB on an M4 Pro.
* The Channels page reads `channel.list` every two seconds while it is on screen and something is live, so a stream's bit rate and its sparkline move, and a destination that is trying again says why on its tile.
* The core takes every platform the page offers (Instagram Live, Kick, LinkedIn Live, X and TikTok LIVE as well as YouTube, Facebook, Twitch, custom and SRT); a test reads the page's table and fails when one is missing.
* `channel.key.add` and `channel.key.remove` are `POST /api/v1/channels/{id}/key/add` and `.../key/remove`, and the destination methods are `POST /api/v1/channels/{id}/destination/add`, `POST /api/v1/channels/{id}/destination` for set and `.../destination/remove`. The three destination methods had shared one path. A test now fails when two methods land on one route.
* A Channels tab for RTMP channels, next to Outputs, loaded the first time it is shown. Add RTMP Channel (on the tab, beside Add destination, under Streams and feeds in Add a source, and in the palette) asks for a name, shows the address as it is typed, and on Create shows the key once with the Server and Stream Key boxes laid out as OBS asks for them, Copy buttons and a QR code for a phone encoder. Each channel is a card with a pulsing dot while live, a row per stream with its size, frame rate, codecs, a bitrate line, the publisher, uptime and the source it feeds, its settings (rename, on or off, key mode, keys with Revoke, auto source, remove) and a strip of destinations with each platform's mark in a ring that shows off, waiting, connecting, live, trying again or stopped, a switch per tile, and the reason in words when one stops. The panel subscribes to `channel.*` only while it is on screen.
* The destination table has Instagram Live, Kick, LinkedIn Live, X and TikTok LIVE, each with a one line hint and its brand colour, so Add destination on the Outputs panel offers them too. An existing output on a Kick ingest is no longer taken for Twitch: the longest matching host wins.

* A channel's stream can be sent straight on to YouTube, Facebook, Twitch, any RTMP or RTMPS server, or SRT, by remuxing the publisher's own bytes. Three new methods, admin scope: `channel.destination.add`, `channel.destination.set` and `channel.destination.remove`. Keys are write only. Each destination has its own threads and a bounded queue that drops whole GOPs when the far end is slow, reconnects on the same own and cdn backoff outputs use, gives the far end the metadata and codec headers again on every connection and then waits for a keyframe, and reports `state`, `kbps`, `reconnects` and an `error` in words. The platform servers and the two retry presets now live in the protocol crate, and the core's outputs read the presets from there.
* RTMP channels, the server half. A channel is a named place encoders publish to on the mixer's one RTMP port, `rtmp://<mixer>:1935/<app>/<stream>?psk=<key>`, and several streams can be live on one channel at once. Seven new methods: `channel.list`, `channel.get`, `channel.add`, `channel.set`, `channel.remove`, `channel.key.add` and `channel.key.remove`, and three events, `channel.changed`, `channel.removed` and `channel.refused`. A key rides as `?psk=`, `?key=`, `?token=` or `?Token=`, or is the whole stream name on a channel set that way; it is shown once when made and sealed in the secret store after that, with only its last four characters read back. A publisher with no key or a wrong one is refused with `NetStream.Publish.Denied` and a sentence, logged, and announced. Taking a key back or switching a channel off cuts off whoever is on air with it. A stream that goes live becomes a source called `<app>-<stream>` by itself, and goes again when the publisher leaves unless a scene holds it, in which case it waits on its freeze frame and comes back with the publisher. Each live stream reports its codec, size, frame rate and bit rate. Channels are kept in `<stem>.runtime.channels.toml` beside the runtime store and survive a restart. See `docs/reference/channels.md` and `docs/how-to/rtmp-channels.md`.
* The ingest plugin's `ingest/discover` is the channel server. Every stream goes through a hub where each reader has a bounded queue: a reader that falls behind loses whole GOPs from the front, counted as `dropped_gops`, and never slows the publisher or the other readers. A tag's payload is shared between readers, never copied per reader. A late reader gets `onMetaData` and the codec headers before its first keyframe. A mixer source reads its stream over loopback on the RTMP port itself, where it used to get a loopback port of its own per publisher; the old relay also wrote every publisher's bytes to every relay, and blocked the publisher on a slow reader. New `streams` tool. Eight 1080p30 6 Mbit/s publishers on three channels with two readers each cost the channel server about 4% of one core.
* The core reads a plugin's `event/<name>` notifications, the form `docs/reference/plugin-protocol.md` documents and the SDK sends. Only an older `event` form was read, so every event an SDK plugin raised was dropped. What a singleton plugin logs now reaches the core's log instead of being drained and dropped.
* The Docker entrypoint clears the lock and socket a previous Xvfb left in `/tmp`, starts a fresh one, and stops with the reason when it did not come up. After a host reboot the old socket was still there, the check on it passed, no X server ran, and every web page source failed with the programme black. Ported from the last LiveboxMix commit.
* Mixer settings, a dialog for the mixer's own settings, drawn from `config.schema` and grouped by section. Save sends only what changed, a refused value is shown in red under its field, and each field then says whether it is in force, used by the next source, or waiting for a restart. Keys still waiting say so the next time it opens. Default under a field puts that key back. It opens from a button at the top of the gear's dialog, which is now called Settings for this page, and from the palette as `mixer.settings`.
* Two new methods, `path.list` and `path.create`. A page walks the folders on the mixer (its home folder, its media folder and the folder its config is in, nothing outside them and no files) and makes a new one. The Record dialog uses them: it opens with `Videos/GodwinMix` in the mixer's home filled in and has a Choose button. So does the media folder in Mixer settings.
* The Programme monitor with multiview off has a Multiview on switch. The Command source in Add sources has an Allow command sources switch above its fields, in force at once, so the add after it works. The tile no longer says it is off unless the config allows it.
* The token dialog no longer names `GODWINMIX_TOKEN` or the config file. It says the token is the one set in Mixer settings, that the mixer never shows it again, and to ask whoever runs the mixer otherwise.
* A preset step says what it does and to what: `does` is `add-key`, `add-source`, `install-plugin`, `open-panel` or `take`, and `target` is an output, a picker category, a plugin, a panel or a source. A plain string is still read as a step with only its text. `preset.apply` and `preset.list` carry the sentences in `steps` as before and the whole steps in a new `checklist`. The six presets' steps are rewritten: none of them names a file, a command or an address any more. Church's used to say to put the stream keys into the `[[outputs]]` blocks of godwinmix.toml and to run `gmx` and open localhost:8080, to somebody already on that page.
* After a welcome tile, Nearly there is a checklist. Each row has the button that does the step (Add key opens the Outputs panel's own key form, Add opens the picker on the right category, Install installs the plugin, Show me brings a panel forward, Put on air takes the source) and ticks itself when the mixer's state says it is done. A step with no `does` is shown as its sentence. The dialog no longer repeats a missing plugin as a command under its own Install button, or prints the config file's path.
* A bar at the top of the page names the settings waiting for a restart, whoever wrote them, read from `config.get`. On a mixer that can be restarted from here it has Restart now, which calls `core.restart` and reconnects when the mixer is back; on one started by hand it says so in one sentence, with no command. Dismissed, it stays away until another setting is waiting or the page is loaded again.
* Import from OBS on the welcome screen is a drop zone. Drop the scene collection on it, or press it to choose the file; the page reads it and sends it to `scene.import.obs` with `add_sources`, then shows what was added, what was left out and why, and an Install button for a plugin a source needs. It used to print a terminal command, three folder paths and the name of a markdown file.
* Installing a plugin from the page waits for the install to finish. `plugin.add` answers at once with a task, and the row read the plugin list straight away and said "Installed, but the mixer has not picked it up yet" while the download was still running, or had failed.
* The notes `preset.apply` returns no longer name `gmx plugin add` or a `gmx` restart.
* A refusal can carry the button that gets past it, as `data.action`: `set-config`, `install-plugin`, `enable-plugin`, `open`, `retry` or `restart`, with a `label` for the button. The same object can ride on an `alert` event. The kinds are in `protocol.json` under `actions` and in `docs/reference/errors.md`. The core now offers one when exec sources are off, a take is inside the minimum hold (for a person, not an agent), snapshots or the multiview are off, the node bridge is off, a source needs a plugin that is missing or switched off, a web page has no browser sidecar, the media folder cannot be made, and when the mixer failed handling a command or a call waited on a held mixer thread. The mixer's reply channel keeps the action, where it used to flatten every refusal to a string.
* Those refusals say what the person can do instead of naming a TOML table, a `gmx` command or a Debian package. The take guard names the hold in seconds. A web page source with no sidecar names `godwinmix-browser` and the `browser.sidecar` setting first, and the Linux package only on Linux; it used to tell a Mac user to install a Debian package and that it was not available on macOS. `plugin.add` given a name no marketplace lists says what it can install and from where. The CLI's own text, where it prints a command, is unchanged.
* The web UI's error toast offers the core's button, and Try again when the core named a wait, disabled until the wait is over. A setting that applies live is changed and the refused call goes again in the same press; one that needs a restart says so and offers Restart now where the mixer can do one. A token set to `confirm = "required"` gets a yes or no in the page, and the call goes again with the confirmation. A missing scope and a missing method are said without the method name, which goes to the console. The Alerts panel and alert toasts show an alert's button.
* The source picker offers to turn a plugin back on when it is installed and switched off. It offered to install it, which answered ok, changed nothing and drew the same offer again.
* The source drawer has Change the address, which removes the source and adds it again under the same id and name, so its places in scenes stay. It used to tell the person to do that by hand.
* Forget the saved token and Reset the layout, in Settings, reload the page themselves. The page no longer subscribes before its socket is open, which could log "core.subscribe was refused" at start.

* `godwinmix` with no config file starts. It writes a starting `godwinmix.toml` where the config would be, logs one line saying so and where, and prints the address to open. It used to exit with "could not load godwinmix.toml" and a shell redirect to type. The file is the example with every sample source and output commented out, the one the desktop app already wrote, so a first run reaches the welcome tiles instead of two cameras that cannot connect. `--example-config` prints the same text, and the desktop app now leaves the writing to the mixer, so the two first runs are one.
* `core.restart`, admin scope. A mixer started with the new `--supervised` flag (or `GODWINMIX_SUPERVISED=1`) answers `restarting: true` and exits with status 75 for its supervisor to start it again; one started by hand answers `restarting: false` with a sentence saying how to restart it, and keeps running. `core.info` reports `supervised` and `restart: {possible, how}` so a page can offer the button only where it works. The systemd unit sets `--supervised` and now has `Restart=always`, because `on-failure` left a deliberately exited mixer down; the compose file and the desktop app set it too. The desktop app starts its mixer again, on the same port, when it exits with 75, has Restart the mixer in its menu, a `restart_core` command for its own page, and answers a `godwinmix://restart` navigation.
* The media folder is made when the mixer starts and whenever `media.list` finds it missing, and that listing carries `"created": true`. The Media panel used to say the folder did not exist and ask the person to create it, while its own Upload button would have. The panel now says "Nothing here yet. Press Upload, or drop a file on the window." and shows an error only when the folder cannot be made. Both recorders already made their folder; a test now holds the built in one to it.
* `scene.import.obs` takes the collection as text in `content`, so a page can send the file a person picked, and `add_sources: true` adds the sources the scenes draw through `source.add` in the same call. The answer lists `sources_added` and `sources_not_added`, each with its reason and, where a plugin is missing, the plugin's name. `path` still works, and `gmx import obs` reads collections with the same importer. It used to take only a path on the mixer's machine and hand back TOML to paste.
* A `test/source` given the type id as its address, as `source.add` asks of a source with no address of its own, shows colour bars. It read `test` as a pattern name and was refused.
* The mixer prints "GodwinMix is running. Open http://.../ in a browser." once on start, whatever the log format.

* Four new methods read and change the mixer's own settings: `config.get`, `config.set`, `config.reset` and `config.schema`. Keys are dotted, as in a preset plan. Every answer says when a change applies: live (the safety rules, the stall policy, the audio ramp, exec sources), on the next source (`[browser]`), or at the next start, with the list of keys still waiting. A bad value is refused with the range or the choices, and nothing is written unless every value fits and the file still loads. The control token is never read back. The GUI dialog on top of these is not built yet.
* `preset.apply` and `plugin.settings.set` edit the config file in place and keep every comment in it. Both used to write the file again from its values, so one click on a welcome tile turned a 506 line commented file into about a hundred bare lines.
* `preset.apply` names only the config keys it wrote as waiting for a restart. It counted keys where your own value won and nothing was written.
* `core.doctor`, over `/rpc` and over `GET /api/v1/core/doctor`, checks the config the mixer was started with. It looked for `godwinmix.toml` in the working directory and reported it missing on a mixer started with `--config`.
* `[canvas]`, `[program]` and `[control]` take a default for each key left out, as the other sections already did. A `[canvas]` with only a width in it used to stop the mixer starting.
* Fixed a segfault in the programme compositor when a source that was on air was removed. A flush stop sent into a slot could free a frame the compositor's scaler threads were still writing. It took about eighty removals to hit on an M4 Pro. A slot is now hidden, and one frame let out, before its flush is ended.
* "Start empty" on the first run screen opens the Default scene's own source chooser. It used to add the source to the mixer and to no scene, so the toast said added and nothing appeared.
* The source chooser reuses a test pattern or media file the mixer already has. It compared against the full address while the core publishes a shortened one, so every scene got its own copy of colour bars.
* Two new methods. `source.duplicate` copies a source the mixer has, and `source.restore` puts back one of the last sixteen it removed, with its id, fader and mute. Undo after removing a source, and paste, use them. They used to send back the shortened address the core publishes, which for a file is `file:///…` and cannot start.
* A source restarting in place no longer sends its flush into the compositor. The flush stops at the first queue past the proxy, which is all it has to wake, so the same segfault cannot be reached that way either, and the last frame stays up until the first new one.
* A plugin's media sockets stay inside the 104 byte limit on a Unix socket address. Past it the address was cut with nothing said and the socket was made outside its own directory, where nothing removed it, so the source failed with "Address already in use" on every later start, across restarts of the mixer. A desktop install put `macbook-pro-camera` at 101 bytes. Long addresses go under the temporary directory, and what a killed mixer left behind is cleared before the next bind.
* The scene chooser's Existing sources list has Remove, which takes a source out of the mixer and closes its camera, with Undo. Delete on a tile only ever meant out of this scene, so a camera once added stayed open until the mixer stopped. The chooser opens on that list when the mixer has a source the scene lacks.
* Every item in the composer can be moved, resized and turned, whatever its plugin lists. The camera and screen plugins list a handle called `resize`, a name the UI does not know, and no `rotate`, so a camera had a cage and four crop edges and nothing else.
* The composer's settings panel for a camera shows the same form as everywhere else (a list of cameras, a list of sizes with Automatic, a list of frame rates with Automatic, a custom size under Advanced) and sends it to `source.set`. It used to write into the scene item, where nothing read it.
* Fit changes the picture. `compositor` has no cover policy before GStreamer 1.30, so Cover drew what Contain drew, on air and in the preview, which ignored Fit altogether. Cover is now a trim to the shape of the box, worked out where an item becomes a placement.
* Blend is no longer offered. The mixer composites video with no alpha plane, where GStreamer's `add` is the same as `over`, and nothing ever read the setting. An imported scene that carries a blend keeps it and says it is drawn as normal.
* A chroma key on a scene item is refused with the reason, where it answered ok and never went on. The programme is composited in I420, which has no transparency; compositing with it was measured at 2.6 times the CPU. A filter that cannot go on is tried once, not twice a second.
* A number whose 0 means something says so: Automatic, Off, Wait for ever, One file, Any free port. The built in test pattern is a list.
* A camera opens wide. Left on automatic, the capture element took its device's first mode, and a MacBook Pro camera lists 1080x1920 first, so a picture Photo Booth shows wide arrived as an upright strip. The plugin now reads the camera's modes and asks for the one of the canvas's shape. The camera form lists those sizes, with Automatic first, and asks for a name in one optional box.
* A mosaic cell is the shape of the sheet. Two tiles, one source and the programme, were two cells of 480 by 540, and a client fitting a cell into a 16:9 tile drew any source as a narrow column.
* A settings schema that marks nothing as advanced is folded by the form itself, so an older installed plugin no longer shows its list of GStreamer element names beside the camera.
* The composer's handles can be reached. A source dropped into a scene fills the canvas, which put its corner handles on the edge of the picture and its rotate handle outside it. The picture now has a margin, the grab radius is 16 px, and the rotate handle steps by the quarter turns the mixer draws. The live preview shows rotation and crop.
* The composer's inspector has Position and size: X, Y, W and H in canvas pixels, and rotate left, right and reset. The inspector also hands the mixer's answer on to the canvas, which it used to drop, so a change made there to a draft is drawn.
* Settings forms open on what a person fills in first. A camera, a microphone and a screen are picked from a list of the ones the machine has, tuning and workaround fields fold into Advanced at the bottom (38 fields across 14 plugin schemas), and a source's settings open with the form of its own kind: the core now publishes each source's `type`, where a camera's settings had been opening as a file's.
* The composer shows the draft it is editing, live. `scene.preview.set` takes a `draft`, and the preview compositor lays it out through the programme's own placements, so an item dragged in the composer moves its video and not only its outline. It used to show the armed scene or the programme, neither of which is the draft. The picture is also fitted to the canvas the outlines use, where it had been a few percent off, and the title carries the scene's name where it carried an id.
* Apply in the composer reaches the programme when the scene is on air. It used to save the scene and leave the old layout going out until somebody took the scene again.
* A scene or source tile keeps its size when it goes on air. The programme monitor's `.program` rule, a centred grid, also matched a tile in the `program` state and shrank its face to 9 by 22 px.
* Every scene has a pencil, beside its tab and on its tile, that opens the composer.
* The Outputs panel's Edit, Reconnect, Remove and Stop recording can be pressed. Every status made each row again, about thirty times a second with a destination reconnecting, so a button held for a tenth of a second was gone before the release. Rows are now kept and written into.
* A custom RTMP destination takes a whole address with the key box empty, on an add and on an edit, which is what its own description promised.
* A mixer started with a relative config path, `--config godwinmix.toml`, can start a camera. The runtime directory was relative with it, and a plugin, which runs somewhere else, could not bind a socket at the address it was given.
* A camera or microphone that is not on the machine is refused with the ones that are. The plugins fell back to the bare capture element whenever the device monitor did not find what was asked for, and that fallback answered with advice to clear an `element` setting nobody had set. The by hand form's Camera box is now a choice of the devices `device.discover` found, by name, so a name typed where an id belongs cannot be sent.
* The capture plugins wait a moment for the bus before reporting a failed start, so the message carries GStreamer's reason.
* The uptime in the header counts on between snapshots.
* The audio meters move. Every meter on the page drew silence, in the Audio tab, on the source tiles and on the header, because nothing ever asked the core for levels: `event/meters` is governed by `ext.meters` alone, and the page named the event and never the ext key. A meter asks for itself now. The first one drawn takes the subscription, the last one to go gives it back, and a page with no meter on it costs the core nothing.
* The Outputs row's numbers follow the mixer. A recording's megabytes and a destination's buffered seconds move while nothing else changes, and a status is sent only when something does, so the row read "0.0 MB sent to the file" for the whole of a recording. The panel reads them back once a second while a row is on screen and stops when there is none.
* "Rename a scene" in the command palette renames one. It was offered only while a scene tile was selected, and the page opens on a strip of tabs, which has no selection, so the row read as unavailable and choosing it did nothing. It now takes the selected scene, the one in hand, or the one on air, turns the tabs back to tiles because that is where a name is edited, and says so in a toast when there is no scene at all.
* Renaming a scene that is on air changes the name in the header and on the programme monitor, and leaves the red frame on its tile. The core names the programme's scene by the name it had when it was taken and never revises it, so every one of those read the old name until the next take. The scene session now resolves that name to an id once and files the current name in the store.
* The + and the pencil on a scene tile say the scene's new name after a rename. Both had the name written into them when the tile was built and nothing wrote it again.
* The pencil's tooltip says "Edit the layout ... in the composer", and a double click on a scene's name renames it. A pencil beside a name reads as rename, and the only ways to rename were F2 and the right click menu.
* Escape out of renaming a scene no longer writes the old name back over a rename that lands afterwards. The blur that followed the Escape committed a second time.

## 0.2.0 (2026-09-15)

The first GodwinMix release, grown from LiveboxMix 0.1.0.

* The core is a library (`godwinmix-core`) with a versioned protocol (`godwinmix-protocol`, api level 1) served over `/rpc` and `/api/v1`, with generated TypeScript, Python and Rust clients.
* Plugins are processes on a documented contract: a manifest, JSON lines on stdio, media over unixfd, shm or a pipe. Twelve first party plugins, an SDK, templates in five languages, a conformance harness, marketplaces with signed installs, and a WASM tier behind a feature.
* Scenes as a document the core owns, a slot pool on the compositor, transitions on control bindings, a composer in the web UI, layouts, presets, themes, an OBS importer and OGraf graphics.
* Nothing runs unless asked: the multiview, thumbnails, preview, audio monitoring and the encoder start with the first client and stop with the last. Idle core measured at 0.012 cores and 37 MB on an M4 Pro.
* Safety in the core, a compact agent surface with MCP over stdio and HTTP, hooks, session replay and an operator eval suite.
* A terminal UI, Companion, Stream Deck, OSC and tally integrations, a node daemon for remote placements over mTLS.
* Desktop app for macOS, Windows and Linux with a trimmed GStreamer bundled; Docker image and a headless quickstart.

Known limits: Linux and Windows builds are verified by inspection and cross checks only until the project's CI runs; browser sources on macOS and Windows need the codec enabled CEF the project publishes; the second canvas is not built.
